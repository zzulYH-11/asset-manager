# User Scenarios (MVP v1 기준)

이 문서는 **MVP v1 스펙**에 근거하여 작성되었습니다. 로그인 및 실시간 시세 연동이 없는 단순화된 구조 속에서, 타겟 페르소나(김주식)가 겪는 핵심적인 사용자 시나리오와 화면 흐름을 정의합니다.

---

## 시나리오 1: 분산된 주식 자산 등록 및 비중 시각화 (CRUD & Chart)

### 사용자
* **김주식** (여러 증권 계좌에 주식이 흩어져 있어 전체 비중을 알기 어려운 대학생 장기 투자자)

### 목표
* 흩어져 있는 자산들을 하나의 포트폴리오로 취합하고, 종목별 투자 비중을 한눈에 시각적으로 파악하여 장기 투자 포트폴리오를 관리한다.

### 흐름
1. 사용자가 웹 서비스(`https://...vercel.app`)에 접속합니다. (별도의 로그인 절차 없이 즉시 메인 대시보드로 진입합니다.)
2. **`자산 현황`** 화면 우측 상단의 **`새 자산 등록 (+)`** 버튼을 클릭하여 입력 모달창을 엽니다.
3. 모달창에 흩어져 있던 미국 주식 정보를 입력합니다:
   * 종목 코드(Ticker): `NVDA`
   * 평균 매입 단가: `485` ($ 기준)
   * 보유 수량: `8` (정수)
4. **`등록하기`** 버튼을 누르면 화면 우측 상단에 *"NVDA 자산이 등록되었습니다."*라는 성공 알림(Toast)이 뜹니다.
5. 대시보드가 즉시 갱신되어, **보유 자산 평가액**(`$3,880.00`)이 상단에 계산되고, 중앙의 **도넛 차트**에 NVDA의 비중이 100%로 렌더링됩니다.
6. 다른 계좌에 있던 `TSLA`(단가 220, 수량 15)와 `AAPL`(단가 175, 수량 10)을 동일한 방식으로 순차 등록합니다.
7. 도넛 차트를 통해 내 전체 자산 중 각 주식이 차지하는 비율(예: NVDA 43.4%, TSLA 37%, AAPL 19.6%)을 한눈에 확인하여 포트폴리오의 편중 여부를 진단합니다.
8. 전량 매도했거나 잘못 입력한 종목은 테이블 우측의 **`휴지통(삭제)`** 아이콘을 클릭하여 포트폴리오에서 즉시 제거합니다.

## 시나리오 2: 거시경제 동향 및 시장 지표 종합 파악 (뉴스 & 지표)

### 사용자
* **김주식** (매일 아침 시장 상황을 공부하며 장기 투자 확신을 다지고 싶은 초보 투자자)

### 목표
* 복잡한 포털 사이트를 방황하지 않고, 장기 투자 의사결정에 필수적인 글로벌 거시경제 지표 9종과 뉴스 10개를 한 화면에서 간결하게 파악한다.

### 흐름
1. 아침에 잠에서 깬 사용자가 웹 서비스에 접속합니다.
2. 하단 탭 메뉴에서 **`시장 지표`**를 클릭합니다.
3. 화면에 렌더링된 9종의 글로벌 지수 카드를 빠르게 스캔합니다:
   * *미국 10년물 국채금리*, *달러 인덱스*, *원-달러 환율*, *공포지수(VIX)*, *WTI 원유*, *금*, *비트코인*, *S&P 500*, *나스닥 지수*
   * 각 지표의 변동율과 상승/하락 컬러 표시(초록/빨강)를 통해 전일 뉴욕 증시의 훈풍 여부와 거시적인 돈의 흐름을 30초 만에 파악합니다.
4. 이어서 하단 탭 메뉴의 **`경제 뉴스`**를 클릭합니다.
5. 정제되어 올라온 **최신 주요 경제 뉴스 10개**의 헤드라인과 핵심 요약 문구를 아래로 스크롤하며 가볍게 읽습니다. (예: 연준의 금리 동결 코멘트, CPI 지수 발표 결과 등)
6. 주가 차트만 보며 불안해하던 이전과 달리, 거시적인 매크로 상황을 종합 이해하며 차분하게 장기 투자 멘탈을 유지합니다.

## 예외 상황 및 처리 규칙

1. **중복 종목 추가 등록 (가중평균단가 갱신)**
   * 사용자가 이미 등록된 종목(예: `AAPL`)을 추가로 분할 매수하여 한 번 더 등록하는 경우, 시스템은 에러를 내는 대신 **Weighted Average (가중평균)** 방식으로 매입 단가를 계산하고 수량을 합산하여 갱신합니다.
2. **잘못된 입력값 방어**
   * 단가나 수량에 문자를 입력하거나 음수를 입력하는 경우, 모달창 폼의 HTML5 유효성 검사 및 JavaScript 체크를 거쳐 요청을 원천 차단하고Toast 경고 메시지를 노출합니다.
3. **서버 API 오프라인 대응**
   * Railway 백엔드 서버나 DB 점검 등으로 API 통신이 지연/실패하는 경우, 화면이 뻗어버리는 런타임 오류(Crash)를 방지하고, 화면 중앙에 로딩 상태를 유지하거나 *"백엔드 서버와 통신할 수 없습니다."*라는 경고 Toast를 띄워 사용자 경험을 보호합니다.

## 화면 흐름 (Screen Flow)

```text
[초기 접속]
    │
    ▼
[자산 현황 탭] (보유 자산 평가액 + 도넛 차트 + 자산 리스트 테이블)
    │
    ├───► [+] 버튼 클릭 ──► [자산 등록 모달] ──► 입력 후 등록 ──► (목록 갱신 및 Toast)
    │
    ├───► [휴지통] 버튼 클릭 ─────────────────────────────────► (목록 갱신 및 Toast)
    │
    ├───► 하단 탭 [경제 뉴스] 클릭 ──► [경제 뉴스 탭] (10개 정제 뉴스 목록)
    │
    └───► 하단 탭 [시장 지표] 클릭 ──► [시장 지표 탭] (9종 핵심 경제 지표 그리드)
```
